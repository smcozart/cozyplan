# Recommended changes: getting cozyplan and cozycode back in step

**Written:** 2026-08-24, from the cozyplan session.
**State at writing:** cozyplan `60380ca` (pushed, CI green). cozycode `83dbbc2` (pushed),
vendored at `68755b9` — **3 commits behind**.

Four items. **The order matters**: doing 3 before 1 re-introduces the defect that item 1 exists
to remove. Items 1 and 2 are cozyplan's; 3 and 4 are cozycode's.

---

## 0. A regression I introduced, and shipped

Owned up to first because it changes what item 1 is for.

cozycode's commit `e9d78c5` — *"Clear what the move made false, and take an absolute path out of
a tracked file"* — deliberately did this:

```
- | vendored from | /Volumes/dev/AI Dev/software factory/cozyplan-src |
+ | vendored from | the cozyplan repository, `smcozart/cozyplan` |
```

The re-vendor in `83dbbc2` regenerated `VENDORED.md` and **put the absolute path back**, against
cozycode's own ADR-0002 (*absolute paths banned and enforced by test*). It is currently in
cozycode's tracked files, on `main`.

**Nothing caught it, and that is the more interesting half.** `PortabilityTest` scans only its own
site — `git -C base_path() ls-files` — and cozycode's root `pre-commit` runs only `state check`.
So **cozycode's own tracked files are checked by nothing**: the rule is declared in cozycode's
ADR-0002 and enforced in three site repos, not in the repository that declares it. See item 4.

My verification was insufficient in a specific way worth naming: I checked that content files were
*unchanged*, and never asked whether a **regenerated** file had re-added something deliberately
removed. A generated file has no diff to review until it is written.

## 1. cozyplan: stop writing an absolute path into `VENDORED.md`

**Why upstream, not in cozycode:** `VENDORED.md` is generated by `plan_tool init --vendor`. Fixing
it by hand in cozycode gets overwritten by the next re-vendor — which is exactly what happened.

The replacement already exists. `50fde96` added a `source remote` field that records
`https://github.com/smcozart/cozyplan.git` automatically — the same information the hand-edit
wrote, derived rather than typed. What remains is to stop *also* writing the local path.

- Keep: `version`, `source commit`, `source remote`.
- Drop or neutralise: `vendored from | <absolute path>`.

Note `doctor`'s new `vendored freshness` row currently *uses* `vendored from` to locate a local
checkout to compare against. If the field goes, that row needs another way to find one — resolving
`source remote` against known local clones, or accepting "not reachable from this machine", which
it already reports honestly. **Do not silently degrade the row to always-reachable-looking.**

A test should assert no generated cozyplan artifact contains an absolute path, so this cannot
regress the way it just did.

## 2. cozyplan: bump `plugin.json`

`.claude-plugin/plugin.json` says `3.1.0`, last set at `51575d8`. There have been **8 commits to
`skills/` and `hooks/` since**, including everything from this session.

Per the plugin documentation: *"If set, users only receive updates when you bump this field."* So
a plugin install is pinned to a `3.1.0` that no longer resembles the code, and `VENDORED.md` will
keep reporting `3.1.0` however much changes underneath it.

`3.2.0` is the honest number: new commands (`hooks selftest`), new behaviour (fail-loud,
`${CLAUDE_PROJECT_DIR}` registration), new `doctor` rows — additive, no removals.

**On the version symptom that prompted this.** A version number "changing" could not be
reproduced. `VENDORED.md`'s `version` field reads `3.1.0` at *every* commit in cozycode's history.
What does change is `source commit` (`unknown` → `a87b570` → `68755b9`), which is correct and is
the field carrying real information. If the observed symptom was something else, it is unexplained
and worth reporting with the two values seen and where.

## 4. cozycode: decide whether the absolute-path ban covers cozycode itself

cozycode's ADR-0002 bans absolute paths in tracked files. Three site repos enforce it; cozycode
does not check its own. Item 0 walked straight through that gap.

This is cozycode's call and its session should make it. Two shapes, both cheap:

- A check in cozycode's `pre-commit` scanning `git ls-files` for machine-specific absolute paths.
  Local tier, working-tree question, consistent with ADR-0012's rule.
- Or accept the gap deliberately and record why — a decision, not an oversight.

Worth noting a generated file is the awkward case for either: it is correct on the machine that
generated it and wrong everywhere else, which is precisely the class ADR-0002 exists for.

## What is already true, and needs nothing

- cozycode's hooks resolve an interpreter at call time and fail loud when none does.
- `cozyplan.plantool` points at cozycode's own in-repo copy, relatively.
- The plugin stays disabled; the vendored copy is the single route; `hooks selftest` reports 4/4.
- `state check` reads the git index, so cozycode's pre-commit gate now catches an ADR rendered
  into Registers and never staged — **the blind spot ADR-0012 recorded is closed.** That ADR was
  correct when written; the premise changed upstream. It deserves an amendment rather than being
  quietly left to read as still-true.
- `ci runs selftest` warns in cozycode: its workflow predates the selftest. One step, one line;
  `doctor` prints the exact command.
